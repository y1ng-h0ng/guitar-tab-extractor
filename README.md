# Guitar Tab Video Extractor / 吉他谱视频提取工具

**Turn guitar-tab tutorial videos into clean, printable PDF scores.**  
**把视频里不断出现、翻页的六线谱自动提取、拼接并整理成可打印的 A4 PDF。**

`Video → Detect tablature → Capture stable pages → Stitch overlaps → Reflow measures → PDF`

This project works directly with tablature that is already visible in video frames. It does **not** listen to the audio, guess notes, or regenerate the score with OCR.

本项目直接处理视频画面中**已经存在的六线谱**：定位谱面、识别翻页、提取稳定画面、去除重复区域，再按照小节重新排版输出 PDF。它**不是听音扒谱工具**，也不会用 OCR 重新生成乐谱。

### Why this project? / 它解决什么问题？

很多吉他教学视频会把六线谱固定显示在画面下方，并随着演奏不断翻页。直接截图通常会遇到重复页面、动态背景、翻页重叠、小节断行和排版混乱等问题。

Guitar Tab Video Extractor 尝试把这套过程自动化，将视频中的已有谱面整理成更适合阅读和打印的连续 PDF。

### Highlights / 核心特点

- 🎸 **Made for guitar tablature** — 针对六线谱，而不是通用视频截图工具
- 🎬 **Video-aware page detection** — 根据谱面变化识别稳定页面和翻页
- 🌐 **Paste a video link** — 粘贴视频分享链接，自动获取视频并生成谱面
- 💾 **Resume and reuse** — 中断续做、跨次运行保留局部修正；只改排版时复用提取和拼接结果
- 🧩 **Overlap stitching** — 自动寻找相邻页面的重叠区域，减少重复内容
- 📏 **Measure-aware layout** — 根据小节线重新分行，而不是机械裁图
- 🔗 **Tie/slur protection** — 尽量避免把跨小节连线拆到两行
- 🖼️ **Preserves the original score image** — 保留原谱面的数字、符干、技巧标记和连线，不重新 OCR 排字
- 🔎 **Review individual segments** — 点击疑点定位原视频、提取片段和相关谱行，只重处理选中的片段
- 🛠️ **Verified local recovery** — 对疑点片段加密采样，逐块检查笔画保留后再采用补救结果
- ✏️ **Reversible local editing** — 框选擦除杂线、保护易丢笔画，逐次撤销并随缓存恢复
- 🏁 **Final barline** — 在整首谱最后一个小节补上“细线 + 粗线”终止线
- 📄 **Printable A4 output** — 自动缩放、分页并生成 A4 PDF
- 🔒 **Local processing** — 视频和谱面均在本地处理，不需要大模型 API

> **No audio transcription · No OCR reconstruction · No LLM API required at runtime**

## Quick Start / 快速开始

### Windows 安装版 / 便携版（无需 Python）

使用 `GuitarTabExtractor-1.1.1-Setup-x64.exe`，按中文向导安装后从桌面或开始菜单打开。也可以完整解压 `GuitarTabExtractor-1.1.1-Portable-x64.zip`，双击 `GuitarTabExtractor.exe`。请保留同目录的 `tabextract-worker.exe` 和 `_internal` 文件夹。

支持 Windows 10 1809 / Windows 11 x64。运行无需安装 Python；链接下载需要联网。本地视频的 PDF 默认保存在视频旁边；链接输出保存在 `%LOCALAPPDATA%\GuitarTabExtractor\output`，缓存保存在 `%LOCALAPPDATA%\GuitarTabExtractor\cache`。可自定义 PDF 位置，并在“缓存管理”中清理缓存。安装和便携两种版本都使用当前用户的数据目录。

退出程序后运行新版安装包即可覆盖更新；卸载保留已生成的 PDF、缓存及原视频。安装包目前未做数字签名，Windows 可能显示“未知发布者”；请核对下载来源和随包 SHA-256。[构建说明](packaging/README.md)提供打包步骤。

### Windows 源码运行

保存保护适用于安装版、便携版和源码版：自动输出遇到同名 PDF 会添加 `(2)`、`(3)` 等编号；自定义文件名已存在时，界面会询问是否覆盖，默认否。重新分行同样遵循此规则。局部修正更新本次会话生成的文件；如果文件被其他程序修改或替换，会停止更新。命令行指定已有 `-o` 路径默认报错，只有显式添加 `--overwrite` 才允许替换；Python API 的 `run_pipeline` / `export_rows` 同样默认为不覆盖。

1.1.1 优化了逐像素颜色计算与相邻视频采样的解码方式，保持原采样帧、分辨率和清洗阈值；采样只保留谱面区域，避免裁图仍占用整张视频帧的内存。在同一台机器上，《夏日潜行》前 30 秒从约 82 秒降至约 26 秒，15 张中间结果和谱行图像逐像素一致。完整 152 秒视频首次生成约 167 秒；只改每行小节数，复用缓存约 2.3 秒。此为具体样例的处理时间，不保证所有视频都达到同样速度，也不代表识别准确率得到同等提升。只改每行小节数或 DPI 时继续复用缓存，无需重新提取。

1. 下载并完整解压项目，不要直接在压缩软件中运行文件。
2. 安装 **Python 3.10+**，建议 Python 3.12，并确保安装 Tcl/Tk 和 pip。
3. 第一次运行时双击 `install_windows.bat` 安装依赖。
4. 双击 `launch_windows.bat` 启动图形界面。
5. 将一个视频拖入窗口（也可点击“选择视频”），或在“视频 / 分享链接”中粘贴链接，然后点击“一键生成”。默认自动定位谱面、安排每行小节数并统一行宽。本地视频的 PDF 保存在视频旁边；链接视频的 PDF 保存在项目的 `output` 文件夹，也可自定义保存位置。

需要固定每行数量时，在“每行小节”中选择或输入 1–8；保持“自动”或留空即可自动分行。“保存过程截图”和“生成报告文件”默认均关闭，需要时再勾选。更新旧版本后，启动脚本会自动补装缺少的拖放和链接下载依赖。

### 视频链接一键生成

支持 HTTP(S) 视频直链及 [yt-dlp 支持的网站](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)中的可访问视频页面，包括含单个链接的应用分享文本。粘贴后直接“一键生成”，无需提前下载。解析、下载和谱面处理均有状态提示，可随时点击“取消”。

可选点击“解析链接 / 分 P / 清晰度”，查看标题、时长、分辨率和平台封面，选择分 P 与当前可访问的清晰度。封面不是谱面识别结果；需要查看实际画面时使用“预览 / 框选谱面”。列表最多显示前 200 个分 P，更多条目可输入具体分 P 链接。B 站“稍后再看”中带 bvid 的链接会转为对应的视频页。

主窗口的“处理时间”支持秒数或 `时:分:秒`，例如 `22.5` 至 `1:20`；留空表示整段，单独留空结束时间表示处理到结尾。本地视频和链接都适用。时间按所选分 P 计算；检查结果中的时间仍对应原视频。为保证精确取帧，链接仍先获取该分 P 的视频流，再只分析所选时间范围。

“预览 / 框选谱面”首次获取视频，随后生成复用下载和框选范围。源码版默认在项目内 `.tabextract-cache` 保留下载副本和处理进度，打包版使用上述当前用户目录，取消或退出后仍可恢复。最终 PDF、可选截图和报告保存在指定位置。视频解析与谱面处理在本机执行，不上传到第三方解析网站。

默认优先选择较高清且兼容解码的 AVC/MP4 视频流；谱面不需要声音，因此不合并音轨。未选择分 P 时使用具体链接所指分 P，集合默认第一项。直播不支持。需要登录、付费、DRM 或受地区限制的视频可能无法获取，程序不自动读取浏览器登录信息。错误信息区分链接失效、登录或权限要求、网络失败、平台暂不支持、清晰度失效和平台临时拒绝访问；403 不会直接认定为需要登录。

### 断点续做与缓存管理

- 自动保存定位、扫描进度（每约 5 秒视频）、完整扫描结果、每个提取片段、过渡补帧和完整拼接结果。重新打开软件后，可在“缓存管理”中载入任务，或重新输入相同视频并点击“一键生成”。未完成的当前步骤可能需补做。
- 只改“每行小节”、DPI 或输出路径时，直接复用提取及拼接结果重新排版；已经成功应用的局部时间、颜色、细节修正也会保留。修改采样频率、谱面范围、颜色模式、处理时间或源文件内容时，会建立相应的新缓存。
- “缓存管理”显示总大小与可恢复任务，可清理过期缓存或一键清理全部。启动处理时自动清理 7 天未使用的缓存，超过 2 GiB 时优先清理较旧项。正在使用的任务受锁保护，可能暂时超过限额；清理不会删除原视频、PDF、报告或主动保存的过程截图。
- 缓存是可清理的临时工作数据，不是永久项目备份；清理后仍可从原视频重新生成，但缓存中的局部修正和下载副本会消失。下载断点续传取决于平台与协议是否支持。
- 命令行默认同样启用缓存。使用 `--no-cache` 可禁用并在退出时清理临时下载；`--cache-dir PATH` 或环境变量 `GUITAR_TAB_CACHE` 可指定缓存位置。

网站改版后，可在项目目录更新解析器（Windows 安装脚本环境）：

```powershell
.venv\Scripts\python.exe -m pip install --upgrade yt-dlp
```

## How It Works / 工作流程

```text
视频输入
  ↓
自动 / 手动定位六线谱区域
  ↓
检测稳定页面与翻页
  ↓
多帧采样并清理动态背景干扰
  ↓
匹配相邻页面的重叠谱面
  ↓
拼接为连续长谱
  ↓
检测小节线与跨小节连线
  ↓
重新分行、补终止线并排版为 A4 PDF
```

项目直接从视频画面中提取和拼接已有谱面，不使用大模型 API，也不通过音频重新转谱。

## Score Region Selection / 谱面框选

程序会尝试自动定位视频中的六线谱区域。

如果自动定位不准确，可以点击“预览 / 框选谱面”，用鼠标重新框选谱面范围，再点击“使用这个范围”。“恢复自动定位”可以取消手动设置。

框选时应尽量完整包含：

- 六条谱线
- 音符和数字
- H / P 等技巧标记
- 推弦箭头、`full` 等文字
- 连音线、符干和符梁

对于不同颜色的谱面：

- 白色谱字叠在暗色画面上：通常保持“自动识别”，必要时选择“白字 / 暗底”。
- 白纸黑字谱面：必要时选择“黑字 / 白底”。

原视频分辨率越高，细小符号通常越容易保留。音符数字、和弦、附点、连线和符干均按多帧一致性保留，容忍短暂的背景干扰或遮挡。H、P、滑音等清楚的小标记会做局部锐化；较淡的符号保留原有对比度，避免被进一步削弱。原视频中本来就缺少的笔画不会凭空补写。

品位数字与谱线上下的小符号按各自的对比度做局部锐化，保留 `0`、`8`、`P` 等字符内部的空隙。短暂遮挡时，紧凑音符只要在严格过半的采样帧中仍有足够清晰的笔画证据，就可以恢复；上伸、下伸及穿过谱线的符干均受保护，原图中的断口不会被直线补齐。仅在一半或更少采样帧中出现的笔画不作为恢复依据。持续静止的背景纹理仍可能混入，需要结合原视频核对。

谱面可以在片头之后才出现或逐渐淡入：程序从最早检测到六线谱的画面开始采样，并据此判断谱面颜色。清理滤波尺寸随谱线间距调整，避免把大字号谱面中较粗的八分音符符尾和连梁当成背景擦除。

对于半透明、低对比度的谱线，优先检查覆盖范围更宽的六条等距线，也检查较淡的线组，避免把密集重复数字的亮横画误认为间距更小的谱线。这样可以尽早识别开头谱面，并用正确的谱线间距保护粗符梁；清洗仍依赖多帧中的实际笔画，不补画原视频缺失的线段。

暗背景上的淡笔画按局部对比度筛选，避免被固定亮度门槛整块抹掉。持续可见的紧凑淡符号会按自身对比度增强；增强仍要求逐像素的多帧证据，不填补原有空隙。自动颜色识别在强笔画不足时继续检查较弱的线条。

相邻画面即使音符形状相似，可见的小节编号不一致时也不会作为重叠内容裁掉；无法确认接缝的片段会分别保留。画面右缘仅露出一小部分的小节，只要仍有可见音符，也会保留并提示核对边界。

接缝匹配同时搜索下一页开头和多个内部区域，减少页首遮挡、截断字符导致的拼接失败。候选仍需通过整段重叠、小节编号图像、共同小节线和歧义检查；滚动轨迹有冲突时不会按静态相似度删掉重复乐句。

如果两个停留画面之间没有重叠，程序会自动补采翻页动画中的连续帧，跟踪谱面滚动位移，再对齐并合成过渡谱面。这样可以保留只在滚动途中出现的音符，并把前后页面连接成连续谱后统一分行。前后两处接缝都必须通过像素匹配和共同小节线检查；没有足够过渡画面或无法确认对应关系时，仍分别保留片段。检查结果会显示通过翻页补帧连接的数量。

翻页位移会从前往后、从后往前交叉核对，少量无法匹配的模糊帧可以跳过，但不会猜测其位置或用它们合成谱面。出现重复乐句时，优先依据视频中的实际滚动轨迹，避免把不同小节误当成重叠内容删除。长椭圆圈住的和弦不会因为弧形边缘被误判为额外小节线；换行时也会为三位数小节编号保留足够空间。确认可拼接后先还原连续谱面，再按完整小节分行。

前后接缝均验证通过后，程序还会对照滚动时不同位置的画面，清理没有随谱面一起移动的吉他轮廓、线缆等背景杂线。同一位置停留再久也只算一次位置证据，避免静止背景压过谱面。清理时保留六条谱线、紧凑字符、附点和穿过谱面区域的长符干；没有足够独立画面可供核对的边缘区域保持原样。背景恰好与谱面重合或形状无法可靠区分时，仍可能留下少量杂线。

对于谱面外围残留的小碎线，只有整块碎片在多个独立位置均缺少支持、且远离音符及符干时，才取消小字符保护并整体移除。只要碎片的一部分仍有谱面证据，就继续保留，避免把字母、附点或符尾削掉一部分。符干保护使用居中的滤波窗口，避免偶数窗口偏移导致顶端少保留一个像素。

DPI 是 PDF 内嵌图像的最低分辨率。导出时保留提取图的原有精度，避免密集谱行缩小时丢失细字和符干边缘；提高 DPI 不能恢复源视频中已经丢失的细节。

## Review & Local Adjustments / 核对与局部调整

1. 一键生成后点击“查看检查结果”，左侧列出全部源片段及疑点。点击接缝、弱笔画、边界或重复提示，可定位对应的视频时间和红框范围。
2. 在同一查看区域切换“原视频画面”“提取片段”“生成谱行”。支持适应窗口、100%、200% 和滚动查看。“相关谱行”用于查看该连续片段进入的最终行，可能包含多行；它不是逐音符定位。点击“全部提示”可查看完整提示。
3. 选中需要调整的片段，修改采样开始/结束时间、颜色模式或“细节保留”系数，再点击“只重处理此片段”。时间限制在原稳定片段内；系数范围 0.5–2.0，默认 1.0，增大也可能保留更多杂线。“恢复默认并重处理”只恢复当前片段。

局部处理不重新扫描视频，也不重清理其他源片段。重新计算选中片段的相邻接缝，并用缓存结果重新拼接、排版；因此相关行和分页可能变化。相邻过渡片段按两侧细节系数的均值重新清理，仍需验证前后两处接缝；两侧颜色相反或无法验证时分别保留。PDF 和可选报告先写入临时位置，成功后替换；取消、提取/导出失败保留原结果，报告替换失败会回滚已替换的 PDF。

核对窗口使用当前会话中的图像；成功应用的局部修正与拼接结果也会保存到处理缓存。更换输入或退出释放内存，之后载入相同任务并一键生成可恢复核对数据。清理缓存或自动过期后不能恢复这些局部修正，但原视频和最终 PDF 会保留。勾选报告可另存疑点位置和片段参数；报告本身不包含视频或可恢复的完整工程。

提示基于图像证据，不识别音高或节奏；红框代表需要人工核对的范围。持续背景纹理仍可能被保留，源画面本身缺失的音符不会补写。

- `视频名_吉他谱.pdf`：整理后的 A4 吉他谱 PDF；最后一个小节会补上标准终止线

## Features / 功能说明

- 自动检测视频中的六线谱区域，也支持手动框选
- 根据谱面变化检测翻页，而不是单纯依赖整个视频画面的变化
- 对稳定页面进行多帧采样，尽量抑制动态背景和播放指示线等干扰
- 直接保留谱面中的数字、字母、附点、括号、连音线、符干和符梁，不重新 OCR 排版乐谱
- 对相邻页面寻找重叠区域并进行拼接，减少翻页造成的重复内容
- 根据小节线切分连续谱面，并尽量在合适的小节边界换行
- 检测跨小节的连线，排版时尽量避免把连音关系拆到两行
- 默认按小节宽度和连线自动决定每行小节数：密集小节少放、稀疏小节多放，也可手动指定每行目标数量
- 所有谱行统一总宽，包括末行；偏短的行优先考虑多放一个完整小节再适度压缩，减少长小节被继续拉宽。过宽行先收紧安全空白，仍放不下时整行横向缩放，压缩幅度最多 15%
- 在最终谱面的最后一个小节补上细线 + 粗线组成的终止线
- 将完整谱表行排版到 A4 页面中，并自动处理缩放、页边距和分页
- 支持中文路径、处理取消、参数检查和跨平台文件打开

## Scope & Limitations / 适用范围和限制

该工具更适合以下类型的视频：

- 谱面位置相对固定
- 画面缩放基本稳定
- 单行六线谱横向翻页
- 相邻页面之间存在一定重叠

对于持续平滑滚动、明显倾斜拍摄、频繁缩放、谱面被大面积遮挡或复杂彩色谱面，自动处理效果可能下降。

图像处理无法恢复视频画面之外、严重模糊或被遮挡的内容。非常细小的技巧符号也会受到源视频清晰度限制。少量与谱面形态相似且长期静止的背景纹理可能被保留下来。

当页面匹配或小节边界不确定时，程序倾向于保留内容并在检查结果中提示，而不是静默删除可能属于乐谱的部分；如果启用了报告文件，这些信息也会写入 `.report.json`。

“每行小节”默认是“自动”，按小节宽度和连线安排每行 1–8 个小节。相比把较短的行大幅拉宽，优先选择多放一个完整小节后适度压缩。各行统一到适合阅读的宽度，末行也对齐；特别宽的行会限制压缩幅度，避免字符过窄。手动填写的数量仍是排版目标：短行在能保留连线、且不会使下一行过短时，也可以多放一个小节。收紧空白时保留字符、附点和符干，空白不足才对整行横向缩放；各行总压缩不超过 15%。

## 局部补救与框选修正

清晰度保护：定位仍可识别低亮度、半透明谱线；提取时则按所在位置至少四条真实谱线的亮度决定是否接纳很暗的笔画，避免把吉他背景纹理、暗竖线和数字周围的碎点一并加黑。白字暗底、黑字白底均适用，同一谱表内局部变暗也单独判断。自动补救使用相同的证据标准，不以带回暗背景作为“改善”。

更新清洗算法后，旧缓存会重新提取一次，保留已有局部时间、颜色、细节系数及擦除/保护框选，并重新计算接缝；无需手动清空所有缓存。请重新点击“一键生成”，已导出的旧 PDF 不会自行变化。

首次提取遇到缺少六线谱、低笔画保留率、清晰度不稳定或图像疑点时，只对该片段增加取帧，最多尝试两种候选：加密采样、选择较稳定清晰的帧并适度提高细节保留。候选必须保留原有笔画、通过小连通块检查，并且确实改善源画面支持的细节或清晰度，才会替换原结果。接缝未确认时最多扩大一次翻页取帧范围，仍须通过前后两侧验证。未改善时保留原结果及核对提示；这不是音乐语义识别，不能保证全曲无漏音。

疑点较多的视频首次处理会更慢；已完成的补救随缓存保存。手动调整片段参数时不会自动再次改变这些参数。升级旧缓存可能需重新提取一次，以保存撤销所需的原始结果；已有局部采样时间、颜色和细节参数会保留。

生成后点击“查看检查结果”，选择片段：

1. 选择“框选擦除”，在“提取片段”图上拖动矩形，松开鼠标后更新 PDF。适用于孤立杂线，避免框住正常谱字。
2. 选择“框选保护”，框住容易被清理掉的笔画。保护只取回清理前仍有图像证据的内容；源画面中不可见的笔画不会补画，也可能同时带回框内杂线。
3. 点击“撤销上次框选”逐次撤销当前片段的操作。红色是擦除，绿色是保护，重叠处保护优先；要擦除已经保护的区域，先撤销相应保护。每个片段最多 100 个框选。

框选在拼接清理之后应用，防止相邻重复画面或过渡帧把已擦除的杂线带回来。框选和撤销复用已有提取结果与接缝，不重新读视频；只改选中片段，最终分行和分页会重新计算。导出失败会保留原 PDF 与编辑历史。框选与撤销历史随处理缓存保存，清理或过期后会消失；它们不是永久项目文件。“恢复默认并重处理”恢复提取参数，仍保留框选，框选请使用撤销。

## 真实视频回归检查

`tests/real_video_cases.json` 固定记录四个本地视频的 SHA-256、取帧位置、谱面范围、人工查看源图后标记的数字/技巧符号/符干/杂线区域，以及接缝预期。源视频和谱面图片不包含在仓库中。

回归包括《夏日潜行》完整的首个稳定片段（0–15.84 秒，按实际提取方式取帧），专门检查背景竖线残留、速度标记与数字被加粗的问题，避免只检查很短的静止画面而漏掉背景干扰。

```powershell
python -m unittest discover -s tests
# 四个原始文件放在指定目录后，启用真实视频检查：
$env:TABEXTRACT_TEST_VIDEOS = 'C:/Users/你的用户名/Desktop'
python -m unittest discover -s tests
# 单独运行并保留对照图片与 JSON 指标：
python -m tabextract.benchmark --videos 'D:/测试视频' --output 'D:/谱面回归结果'
```

未配置视频目录时，真实视频用例明确跳过；配置后缺失文件或指纹不符会报错。检查涵盖标注区域的墨迹量、符干纵向覆盖、杂线残留、真实滚动接缝位移，以及局部擦除不改变旁边笔画。报告包含源码指纹和测试清单指纹。局部图像检查不能代替整首曲目的音乐校对：`無路矢` 的一个同谱面测试对在旧版本中已无法可靠去重，仍作为已知问题单列；只有正确去重或继续完整保留两段才允许通过，不能以删去内容来降低疑点数。

## CLI / 命令行

```bash
python main.py "视频.mp4"
python main.py "视频.mp4" -o "输出.pdf"
python main.py "视频.mp4" --bars-per-row auto
python main.py "视频.mp4" --dpi 300 --bars-per-row 4 --sample-fps 6
python main.py "视频.mp4" --report
python main.py "视频.mp4" --debug-dir debug
python main.py "视频.mp4" --region X Y W H --polarity bright
```

常用参数：

- `-o / --output`：指定输出 PDF 路径
- `--sample-fps`：设置翻页检测采样频率
- `--dpi`：设置 PDF 内嵌图像的最低 DPI，不降低提取图的原有分辨率
- `--bars-per-row`：默认 `auto` 自动分行，可填写 1–8 自定义每行目标小节数；两种模式均统一所有行的长度
- `--report`：额外生成 `.report.json` 检查报告；默认不生成
- `--debug-dir`：保存中间处理截图；不指定时默认不保存
- `--region`：手动指定谱面区域
- `--polarity`：指定谱面明暗类型

不同视频的谱面坐标通常不同，因此 `--region` 更适合在已经确定区域坐标时使用；一般情况下建议先使用自动定位或图形界面框选。
